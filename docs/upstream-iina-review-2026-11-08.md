## Order of work

1. Update the pinned dependencies with the native Metal interop, custom render API, and VideoToolbox/AVFoundation fixes carried forward. The dependency work is removing the unused Vulkan integration. The merged IINA dependency bump is a packaging reference. YINA has different renderer and ABI requirements.
2. Adapt the async playlist and first-frame sequencing from #6489 in the playback-state rewrite. Use YINA's existing async client and preserve its current behavior for local playlists, Shared Show, remote recovery, and first presentation. Adapt #6516 as a small independent ownership fix before expanding asynchronous event consumers.
3. Rewrite PiP around explicit video-host ownership and native transition completion. The upstream geometry and duplicate-callback fixes supply regression cases. The URL-open proposal supplies a presentation policy to carry into the rewrite. YINA already has the PiP transport controls and paused drawable resize behavior.
4. Keep energy and renderer tuning tied to YINA's traces. The IINA candidates below do not establish the cause of YINA's intermittent fullscreen-to-PiP stutter. YINA's traces describe render, handoff and window timing without observing the visible compositor output. [Local PiP lifecycle and trace notes](pip-window-lifecycle.md)

## Candidates with a local gap

| --- | --- | --- |
| Open `feefc3ed` | **Adopt the ownership fix independently** | In `MPVController.handlePropertyChange`, the plugin closure captures `mpv_event_property` and dereferences `property.data` on main. The mpv event loop can invalidate it on its next `mpv_wait_event` call. The string path additionally binds a C string pointer as Swift `String`. Copy owned values on the event queue, interpret flags as C `int` and strings as pointers to C strings, and keep listener lookup and event delivery on main. Exercise nil/none, string, flag, numeric values and successive events delayed behind the main queue. YINA already implements string and node copying for its async replies, so use that convention where it fits without changing plugin event payload semantics unnecessarily. [IINA #6516](https://github.com/iina/iina/pull/6516), [libmpv event lifetime and formats](https://github.com/mpv-player/mpv/blob/v0.42.0/include/mpv/client.h) |
| Open `6ed2929a` | **Adapt for the playback-state rewrite** | `playFileInPlaylist`, `navigateInPlaylist` and `notifyWindowVideoSizeChanged` still query or mutate pause synchronously. Take the separation of user pause, pause while loading, accepted/rejected step and first-frame readiness. Reuse `MPVAsyncClient` (`e996f49a`), its reply IDs and invalidation, and the fork's single-node playlist snapshot. The PR's per-entry mpv reads would regress that snapshot. Order or invalidate replies by media/transition generation so stale results cannot resume a later item. Keep audio from starting ahead of first video, preserve the previous-at-first-item rewind, and retain remote recovery, Shared Show, renderer/force-window initialization, plugin events and audio-only readiness. YINA's FFmpeg scanner already cancels queued/running operations and releases decoder resources, but lacks the PR's AVIO interrupt callback for a blocked read and all of its scan checkpoints. Port cancellation separately if useful with the updated FFmpeg stack. [IINA #6489](https://github.com/iina/iina/pull/6489), [closed unmerged companion tests #6492](https://github.com/iina/iina/pull/6492), [October review](upstream-port-review-2026-10-14.md) |
| Open `c881966f` | **Stage after #6489 semantics** | #6490 stacks on #6489 and adds scroll/seek attribution so momentum cannot seek into a newly loaded item and a scroll crossing EOF carries the intended play state. YINA's relative seek path still calls blocking `mpv.command(.seek)`. Extract the last commit's gesture/command attribution if a fixture confirms the boundary failure. Reuse YINA's seek modes and keep relative seek, exact seek and external/Shared Show commands distinct. [IINA #6490](https://github.com/iina/iina/pull/6490) |
| Open `d1279e80` | **Adapt PiP URL intent in the rewrite** | YINA opens the URL and then calls `enterPIP`. Model desired presentation independently of native PiP attachment and defer the actual move until a valid host exists. Test new and reused player, network opening, `full_screen=1` precedence, return from PiP, and closing during load. Retain YINA's no-restore-on-close and fullscreen Space behavior. [IINA #6607](https://github.com/iina/iina/pull/6607) |
| Open `a6466f20` | **Take the idempotence case into fullscreen/PiP work** | Upstream ignores a duplicate AppKit `windowDidExitFullScreen` when already windowed. YINA still runs the rest of its exit handler after that duplicate. Preserve its existing recovery for a genuine late exit callback following a failure, then ensure each real transition performs cleanup once. Test Mission Control, Space changes, fullscreen exit failure and PiP close during the same sequence. [IINA #6558](https://github.com/iina/iina/pull/6558) |
| Open `980437a7` | **Consider an explicit video-output failure state** | Upstream gives a pending window a one-second fallback when a selected but undecodable video stream never triggers reconfiguration. YINA's `pendingShow` normally resolves on size notification, with special handling for no selected video. Prefer a media-scoped fallback with an explicit no-video/error presentation and cancellation on stop or replacement. A slow valid first frame needs its own state, so the upstream timer should not unconditionally mark playback ready. [IINA #6530](https://github.com/iina/iina/pull/6530) |

For PiP, verify native fullscreen Space preservation, a nil intermediate view host, paused seek and resize, no reveal of the original host while entering, and close/reenter during an unfinished handoff. The paused drawable-size redraw, subtitle panel restoration, and single video-view ownership are existing fork behaviors to preserve. [Local PiP subtitle behavior](pip-subtitles.md)
