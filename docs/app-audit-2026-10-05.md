# Whole-app audit — 2026-10-05

Scope: current `meh` source, installed Nightly `202610051449`, dependency linkage and ancestry, existing investigation notes, and isolated optimization tests. The running app was inspected read-only; no windows, media, or user settings were operated. This is an architecture, cleanup, and performance audit, not exhaustive runtime or security certification. Findings below are recommendations, not implemented source changes.

## Findings and priorities

| Priority | Finding | Evidence / confidence | Proposed change and validation |
|---|---|---|---|
| First | Utilities history button invokes the wrong operation | Confirmed: `SettingsPageUtilities.content()` binds “Clear playback history” to `clearCacheBtnAction`, also reusing the same thumbnail-size label in both rows. | Bind the history row to the history operation with its own views. Also clear `HistoryController`'s in-memory state through its API: the existing history selector only deletes the file and recents, allowing a later history save to restore cached entries. Verify history, recents, progress, and thumbnails independently. |
| First | Plugin WebSocket ownership cycle and incomplete teardown | Confirmed source cycle: API strongly owns `server`; `server.delegate` strongly owns API. API inherits an empty `cleanUp`. `stop()` only cancels listener; replacement cancels only the previous listener. | Make the delegate class-bound and weak; explicitly stop accepted connections, detach listener/connection callbacks, clear delegate and managed handlers on replacement/unload. Listener bound-method callbacks are another retention edge. Verify repeated create/start/replace/unload and late cancellation callbacks. This is conditional on plugins using this API; it does not explain all playback memory. |
| Next | Idle player pool retains the maximum number of created players | Confirmed ownership, unmeasured cost: static `playerCores` strongly retains cores, reuses idle ones, and has no retirement limit. Shutdown is intended for app termination. | Retain one warm core; retire surplus idle cores only after renderer/plugin/background-task shutdown is safe. Measure opening/closing multiple players and reopening latency before choosing a limit. |
| Next | Preview memory survives stopping until another file initializes it | `info.thumbnails` holds decoded frames; explicit clearing occurs during new-file initialization/generation, not `stop()`. Default generation requests 100 intervals, including endpoints. | Release idle previews when no consumer needs them, or use a bounded decoded-frame cache. Keep thumbnail generation tickets, Now Playing artwork, and disk-cache reuse correct. |
| Next | UI polling still synchronously queries mpv | `syncUI(.time)` calls `syncPosition()` before the rounded-position skip; position/end-of-file and network duration/cache queries remain synchronous. Paused/hidden local playback already stops its timer. | Measure a hot trace; consider observer-fed position/cache state or asynchronous snapshots. Preserve seek/end-of-file/millisecond display behavior. Do not merely reduce polling until sluggish controls become visible. |
| Later | History scaling has no explicit entry budget | `HistoryController.read()` reads the whole archive; each addition searches the array and rewrites the whole archive. This is durable user history, not automatically a leak. | Benchmark large histories; consider coalesced writes, indexed lookup, and user-controlled retention. Do not silently discard history. |
| Later | Settings views remain cached once visited | `SettingsWindow.cachedPageViews` and page `builtSections` retain views. Releasing only the outer dictionary would not release all controls. | Measure settings-only growth and binding teardown; laziness or selective reclamation needs both ownership layers. Eleven pages are a bounded cache, not proof of a leak. |
| Cleanup | Restore suppressed alerts currently restores nothing | `resetSuppressedAlertsBtnAction` explicitly says the suppressible alert was removed and only shows a success message. | Remove the inert row or introduce it only when suppressible alerts exist. Small UI simplification, negligible RAM saving. |
| Cleanup | Two dependency acquisition paths can disagree | Locked Metal manifest/build exists; `other/download_libs.sh` still downloads upstream IINA dylibs and an unpinned latest yt-dlp. | Retire or clearly restrict the legacy downloader so it cannot silently replace the custom stack. Preserve required plugin acquisition deliberately. |

The WebSocket and history findings were discovered in this audit and are not covered by the existing passing optimization tests. Keep them separate from previously fixed logger/timer/FFmpeg retention issues.

## What can be cut

Installed logical file sizes total approximately **120 MiB**: Frameworks 67.5 MiB, executable 47.0 MiB, resources 5.5 MiB, and small extension/signature overhead. Disk size is not process footprint.

1. **Best dependency-size experiment: playback-focused FFmpeg.** `libavcodec.63` links x265 (7.26 MiB), SVT-AV1 encoder (2.92 MiB), x264 (1.22 MiB), and LAME (0.22 MiB): about 11.6 MiB of external encoder libraries. Rebuild FFmpeg without unused video/audio encoding libraries, then rebuild/repackage the matching stack. Keep required screenshot/image encoders and audio/video decoders. This is an upper-bound library-size opportunity, not a guaranteed RAM or final-bundle saving. Validate screenshots, filters, unusual formats, streaming, and plugin workflows.
2. **Do not delete linked dylibs.** An executable/direct-library linkage scan found no top-level packaged dylib without a reference. Dependencies must be removed at build configuration level, not from the installed bundle.
3. **Keep shaderc.** `libplacebo.365` directly links `libshaderc_shared.1`; the build explicitly enables shaderc. Lack of references in Swift says nothing about this native dependency. Removing it breaks the current renderer.
4. **OpenGL removal is a later compatibility decision.** Metal is enabled in standard configurations, but GL code remains behind compilation conditions. Remove it only after SDR/HDR, PiP, fullscreen, resizing, snapshots, and failure-path parity are demonstrated. It is not the next memory fix.
5. **Icons and framework localization are small secondary savings.** Resources are only 5.5 MiB total. Validate Finder document icons and symbol availability before replacement. Any Sparkle localization stripping belongs before final signing and must preserve framework resources/signature validity.
6. **Legacy migrations are compatibility boundaries.** Establish a supported import cutoff before removing old color/history/profile migration. Persistence names retained from IINA are not automatically obsolete.
7. **Product cuts need an explicit feature decision.** Plugins, Safari extension, online subtitle search, Live Text, mini player, and Inspector can be made optional or removed, but none should be deleted merely because it is outside the main playback window. Their user value and idle cost differ.

## mpv: can and should we update?

**Can: yes, through a coordinated custom-stack rebuild. Should: no blind replacement or urgent stable-version bump is justified by this audit.**

- Installed version string: `mpv v0.41.0-dev-g97179bce7-dirty`.
- Manifest pin: `lhc70000/mpv` at `97179bce7ed980c53647d6344916f632fe689e9e`, dated 2026-06-28. The dirty source includes tracked local patches to AVFoundation pause/resume, Metal VideoToolbox/header installation, and macOS conditional compilation.
- [Latest upstream stable release is 0.41.0](https://github.com/mpv-player/mpv/releases/tag/v0.41.0), commit `41f6a64`. Local full-history ancestry checks confirm this release is already an ancestor of our pin: there are 822 commits after that release on the pinned history. The `dev` version string does not mean we lack stable 0.41 fixes.
- Specifically, the listed AVFoundation memory-leak fix (`59d5f774a`), wrapped-AVFrame cache limit (`b72d6aa0e`), and demux packet-pool cleanup (`52525dceb`) are already ancestors of our pin. Updating solely for those fixes offers no new benefit.
- Our pin introduces [experimental gpu-next support in libmpv](https://github.com/lhc70000/mpv/commit/97179bce7ed980c53647d6344916f632fe689e9e), including `render_mtl.h`, with a matching custom libplacebo fork. The related [upstream render-API proposal remains draft](https://github.com/mpv-player/mpv/pull/16818). Stock mpv or Homebrew dylibs are not a compatible drop-in for this integration.
- The manifest also pins libplacebo `a9629687`, FFmpeg 9.0.1, shaderc 2026.3, SPIRV-Cross, and libdovi. Treat headers, native ABI dependencies, and patches as one stack.

An update trial should choose reviewed commits from the matching forks, identify relevant fixes since the current base, reapply/review our patches, build outside the installed app, and compare identical workloads. Required gates: renderer creation, first frame, SDR/HDR/Dolby Vision, hardware decoding, audio output/pause, seeking, subtitles, screenshots, PiP/fullscreen, SMB/network media, and sustained footprint/frame pacing. Replace the installed stack only after these gates pass. Updating is maintenance work, not an assumed RAM optimization.

## RAM: relax the target, keep the evidence

**Yes: stop treating a low absolute memory number as the goal.** VideoToolbox decode surfaces, HDR output textures, GPU caches, demux buffers, and previews consume real memory to provide smooth playback. Default `defaultCacheSize` is 153600 KiB (**150 MiB**), passed to mpv's demuxer limit; that is a limit, not a guaranteed allocation or the whole process budget. Three Metal drawables are configured. Benchmarking two may save one output surface but can alter frame pacing.

Read-only snapshot of the already-running installed build:

- Physical footprint **472.1 MiB**, lifetime peak **496.3 MiB**; sampled CPU **0.0%**.
- Default malloc zone reports approximately **140.6 MiB allocated**. Graphics categories include 164.5 MiB virtual IOSurface regions and 132.5 MiB owned-unmapped graphics regions. These categories are not additive explanations of physical footprint: residency, swapped storage, shared surfaces, and accounting overlap matter.
- Much writable memory is swapped in this snapshot. A small RSS value would therefore be misleading. Large JavaScript reserved address ranges are not allocated RAM.
- This snapshot does not establish playback state, long-session behavior, leak freedom, or an improvement over older measurements. WebKit helper-process footprint is outside the main-process summary. System-wide swap counters are cumulative and cannot be attributed to yina.

Existing investigation notes reported 658 MiB idle versus 939 MiB during later playback, without capturing the reported CPU spike. Different workloads and states are not a leak proof; graphics residency remains a hypothesis, not a conclusion.

Use acceptance criteria based on **growth and impact**: footprint plateaus during the same workload; repeated open/close/plugin-unload cycles do not stack retained resources; idle/closed-player memory falls appropriately; memory pressure and swap activity remain acceptable; playback does not stutter or waste sustained CPU. Do not lower cache limits or disable HDR/video-track rendering just to improve a number. First target the confirmed WebSocket cycle and retained surplus players/previews.

## Verification and continuation order

`bash other/tests/optimization-smoke.sh` passed this audit: selected-frame decoding, v2/v4/corrupt-cache handling, atomic replacement/concurrent eviction, bounded logs/coalesced notifications/full export, timer callback release/cancellation/unload, and Address Sanitizer FFmpeg decoder-failure/HDR ownership checks. Two existing enum-conversion warnings remain in FFmpeg image creation. These checks do not establish whole-app runtime correctness.

Recommended order: (1) Utilities action correctness; (2) WebSocket teardown; (3) controlled player/preview lifetime measurements and fixes; (4) playback-focused dependency build experiment; (5) split playback/window orchestration modules; (6) continue documented settings slices. Keep manual startup/menu/filter/Inspector/keyboard/recents checks from `cleanup-tracker.md`; isolated checks and successful signing do not replace them.

This audit changes documentation only, so no new app build or dependency update was performed.
