# Watch Together and shared queue

Watch Together starts only when a person chooses **Host Watch Together** or follows a named host in the Shared Show control. Another participant's saved progress never moves local playback by itself. The host publishes an ordered, show-local playlist and its current episode under `.yina/queues/`, alongside its live progress record. Entries outside the selected show folder, network URLs, aliases that escape the folder, and `.yina` metadata are excluded.

Following reads the host's queue as a separate, read-only session list. It does not inject the host's full playlist into the follower's mpv playlist. When the host changes episode, YINA checks the exact queued target on a utility lane and opens it with automatic folder loading disabled. A missing or partially downloaded managed episode stays out of playback; status says it is waiting and checks again at a bounded cadence. Leaving following keeps the episode currently open. A local open, playlist edit, seek, pause, rate change, or stop takes control back immediately and cancels a still-pending remote file preparation.

At a natural end of file, the host queue has no current item while waiting for the next episode. Followers keep their session and wait; they do not reopen the finished file. An explicit host stop publishes a stopped record and ends following. Freshness limits and increasing record revisions reject stale or replayed host state. If the share disappears, local playback continues and the follower waits for it to return.

The production-source session fixture covers queue order, cross-episode changes, missing and partial targets, rapid target changes, canceled preparation, old host records, natural EOF, and explicit stop. A still-pending preparation can be canceled; a file load command already accepted by mpv may complete, after which the session stops applying remote controls. A real multi-computer SMB session and the native menu flow remain to be tested.
