## Implemented follow-up: #6496 and #6495

`JavascriptAPIUtils.exec` now clears stdout and stderr readability handlers as soon as either pipe reaches EOF, before attempting UTF-8 decoding or calling hooks. Both handlers are also removed when process launch fails. Existing process wait/promise scheduling is retained; this does not claim to resolve all process-output synchronization or plugin queue latency issues.

`BufferIndicatorView` now stops its progress animation in `viewDidHide` and restarts it in `viewDidUnhide`, following #6495's snapshot. Network opening no longer restarts it independently of visibility.

`python3 other/tests/eof-spinner-smoke.py` exercises the production handlers and view with isolated dependencies. It verifies EOF cleanup while the serial plugin wait queue is blocked, preserved stdout/stderr output and hooks, launch-failure cleanup, AppKit hide/unhide callbacks, local/network opening, buffering and seeking. All passed. Signed build `202610140818` built, verified and installed. The user's plugin workload and fullscreen frame-rate improvement remain unverified. Next recommended work is staged #6489, followed by the adapted mpv race fixes.

## #6472 validation and limitation

`python3 other/tests/apac-fallback-smoke.py` exercises the production decision with isolated track fixtures: APAC-first fallback, already-selected audio, unknown selection, non-APAC-first, missing alternate, empty tracks and unknown codec. All passed. Signed Nightly build `202610140811` built, verified and installed through the repository workflow; actual iPhone APAC-file playback remains unverified.

This preserves upstream's accepted limitation: `aid == 0` cannot distinguish decoder failure from audio deliberately disabled by the user or watch-later state, so the APAC/two-track case can override that disabled choice. The fallback uses upstream's track-2 assumption. If future FFmpeg support selects APAC successfully, the `aid == 0` condition avoids fallback.

PR status and patch snapshots are time-specific; recheck them before each subsequent port. The plugin probe establishes the local pattern's failure mode, not that the user's installed plugins currently trigger it.
